无限隧道

一条数学闭合的隧道，一个不需要骨骼动画的滑手，一套可以一直往下出的预设。 v0.1 是一个构想；这一版把它拆成能施工的工程：目录、数据契约、帧预算、里程碑和判死门。

32.8 s一圈 @9m/s

01样机 · 先看结果Live Prototype

下面这一帧是可直接运行的 2D Canvas 样机，不到 600 行，零依赖。它不负责证明 Three.js 能跑，它只负责证明三件事：构图成立、速度舒适、循环看不见。

怎么读这一帧：发光拱肋每 9m 一道，是隧道里的钠灯灯带；它们沿闭合曲线退向消失点，所以「永远向前」不需要长度，只需要闭合。 点「跳到接缝」会直接跳到环的接缝处——你能看见它被一次过曝光吃掉。这就是正式版隐藏接缝的手法。

样机与正式版的关系：取景、光比、循环逻辑、预设字段完全一致；差别只在渲染器。样机用线条光（零依赖、可截图自检），正式版换成 Three.js 的马蹄形管壁、湿路面材质与体积雾。换句话说，这一页的代码就是产品原型，也是数据契约的活文档。

02一页纸One Pager

把一条闭合的 3D 曲线当轨道，把一个剪影滑手绑在曲线上，把灯光、雾、机位做成可组合的预设—— 产物不是一个视频，而是一台会一直往前开的机器。换隧道只换数据，换角色只换一个轮廓。

三个判断（它们决定了后面所有取舍）

01 · 无限由闭环保证

不由素材长度保证。295 m 的路径首尾相接，几何、纹理、灯光三相同周期，于是「永远向前」是一个数学事实，不是一个剪辑技巧。

→ 内存恒定，帧率恒定，可跑八小时

02 · 情绪由光和剪影承担

不由模型精度承担。人物亮度压到 8% 以下，只需要一个可信的轮廓和重心；代价是省掉整套骨骼绑定、动画资产与版权谈判。

→ 角色成本从「两周一个」降到「半天一个」

03 · 靠「每圈 1% 的不同」留住人

不由首帧惊艳承担。壁纸要被看几个月，不是三十秒。第 N 圈墙上多一道门、远处多一辆车，成本几乎为零，感知价值最高。

→ 这是唯一能让人「留着不换」的理由

不做什么（v1 的边界，写死，防止范围失控）

  • 不做叙事解谜。没有目标、没有关卡、没有失败。桌面不需要第二个游戏。
  • 不做操作玩法。默认零交互；可选的三件交互全部默认关闭。
  • 不做角色商城。角色是轮廓，不是商品。v1 只做两套剪影。
  • 不做在线加载。所有资源本地化、相对路径、可离线运行——这是 Lively 环境的硬约束。
  • 不做真实运动模糊。用「拉长的灯光」表达速度，比后处理便宜且更干净。

产品定位一句话：不是「一段能动的壁纸」，是「一个可以一直挂着、并且会慢慢变的隧道」。前者卖一次，后者能卖一年。

03美术圣经Art Bible

壁纸是被看的，不是被玩的。所以第一个要定死的不是代码，是三张锚定帧——所有实现都要能复现这三张。

锚定帧 A · 入弯

灯带从左上斜切进来，弯心在左。滑手贴在路面上，重心压向内侧，板底反出一条冷光。画面几乎全黑，只有三道亮线：灯带、路缘、板底。

锚定帧 B · 出洞口

0.4 秒过曝。白光从消失点漫过来，吃掉整张画面，只留一个更黑的剪影。接缝就是在这里被抹掉的——观众以为是被光晃了一下。

锚定帧 C · 长直道

灯距被拉开，两道灯带退成平行线。滑手成为画面里唯一的黑色形状，速度感全靠灯带掠过眼睛的频率。

硬约束（可量化，可验收）

维度规则数值 / 做法为什么

三套预设的色板

sodium · 钠灯山体隧道

主色 #ffab4d，凌晨四点、湿沥青、钠灯的橙。默认预设。

主色 #d6e9ff，隧道养护作业的灯，灯距更密、节奏更硬。

主色 #3fe3ff，城市下穿道 + 广告灯箱，给「夜班人群」的那一套。

五条禁令

  • 不许速度线。线条会暴露「这是特效」。速度用灯带的掠过频率表达。
  • 不许镜头抖动。这是壁纸，抖动会让人晕，且八小时后是折磨。
  • 不许 FOV 呼吸。视场角是世界观，不是情绪工具。
  • 不许常驻 UI。任何文字、按钮、水印默认不出现。
  • 不许真实运动模糊。代价高、效果脏，不如把灯拉长。

04体验规格Experience Spec

壁纸的时间尺度和短片不同：短片是 90 秒，壁纸是八小时。所以循环必须分三层：看得见的、感觉得到的、说不出来的。

层周期改什么目的
主环32.8 s位置 s 走完 295 m，回到原点「一直在动」，不被察觉的重复
大周期18 min色温 ±400 K、雾密度 ±15%、灯带相位漂移 ±1.5 m「好像不一样了」，但说不出哪里
极慢漂移8 h只改一个参数：天光颜色从夜到晨挂一整天的人，傍晚会发现「天亮了」
微事件3–7 min远处车灯 0.8 s / 墙上一道涂鸦 / 一只飞虫 / 通风机低频「它在发生什么事」的钩子

首次 90 秒规则：启动后 90 秒内必须出现至少一次能被明确注意到的变化（一次过曝出洞、一辆对向车灯）。否则用户会怀疑壁纸卡住了，然后关掉它。

交互边界

  • 默认零交互。移动鼠标、点击画面，什么都不发生——这是壁纸的礼貌。
  • 可选三件（设置里默认关闭）：双击暂停 / 滚轮调速 / 长按显示小时钟。
  • 暂停时必须是一张好静帧。静止状态会被截图，也会被当成「桌面背景」用。
  • 切换预设 < 1 s，且不重建整条曲线（只换材质与灯光参数，必要时换路径）。

桌面可读性预算

这不是审美问题，是可用性问题。把壁纸放在 20 个 32 px 图标后面，仍然要能一眼找到图标。

  • 中心 40% 区域平均亮度 ≤ 22%，对比度 ≤ 2.5:1。
  • 高光只允许出现在消失点与灯带上，不落在图标区。
  • 提供「省电模式」：亮度 −30%，灯带减半，帧率降到 20。

模块职责与体积预算

模块只做一件事行数预算禁止
core/loop闭合曲线 + 弧长表 + 任意 s 取点/切线≤ 120禁止碰材质
core/frames重力对齐标架，退化保护≤ 60禁止引入 RMF（v1）
core/tube截面函数 → 环形/实例化几何≤ 180禁止读预设
core/camera三种机位、阻尼、弯道 roll≤ 110禁止写 DOM
core/budget帧时采样与降级阶梯≤ 90禁止改用户设置
core/rng种子随机，保证每圈装饰一致≤ 30禁止 Math.random
scene/rider程序化姿态 + 弯道侧倾≤ 160禁止骨骼动画（v1）
scene/events微事件时间轴与触发≤ 140禁止阻塞主循环

为什么标架不用 RMF：旋转最小化标架（RMF）在数学上更漂亮，但相机和路面会跟着管子一起滚——壁纸里滚镜头等于劝退。v1 用重力对齐标架（世界向上剔除切向分量），路永远是路面，镜头永远不歪。RMF 留给 v2 的海底/太空管。

08运行时管线Frame Pipeline

壁纸是常驻进程，所以每一帧都要有预算。下面是 60 fps（16.6 ms）下的分配，以及 30 fps 上限档（33.3 ms）的余量。

阶段做什么60fps 预算超支后的动作
0 · lifecycle暂停/恢复、可见性、切屏0.1 ms—
1 · advances += v·dt，取弧长点与切线0.1 ms—
2 · camera机位求解 + 阻尼插值0.3 ms降阻尼 → 直跟
3 · cull可见环窗口（前后 60 m）0.3 ms窗口缩到 40 m
4 · tube环形几何绘制 / 实例化4.5 ms环距 ×1.6
5 · rider姿态求解 + 侧倾0.4 ms固定姿态
6 · light & fog灯带、天光、体积雾2.5 ms雾改屏幕空间近似
7 · post颗粒 + 暗角 + 接缝过曝1.2 ms颗粒关
8 · headroom留给宿主与 GC7.2 ms—

主循环（伪代码）

function frame(now) {
  dt = min((now - last) / 1000, 0.05);   // 夹住 dt：切回前台不会瞬移
  last = now;

  if (paused) { requestAnimationFrame(frame); return; }

  s = (s + speed * dt) % loop.length;       // ← 无限的核心只有这一行
  if (s < prevS) flash.trigger();          // 跨过接缝：过曝掩体
  prevS = s;

  camera.solve(s, dt);
  tube.beginFrame(s);                     // 只更新可见环窗口
  rider.pose(s, curvature(s + 6));     // 预读前方 6 m 的曲率做侧倾
  lights.update(s, tSlow);
  atmosphere.update(s, tSlow);

  budget.sample(dt);                     // 滚动平均 → 触发降级阶梯
  renderer.render();
  requestAnimationFrame(frame);
}

接缝掩体：三层同周期 + 一次过曝

  1. 几何同周期——路径闭合，环窗口按 s % length 取，第 0 环与第 N 环是同一个环。
  2. 贴图同周期——UV 用弧长归一化，u = s / length，保证接缝处纹理连续。
  3. 灯光同周期——灯带间距必须能整除周长：length / spacing 取整后回写 spacing，否则接缝处会错半个灯。
  4. 过曝掩体——第 0 米处放一个「洞口」，跨过时 0.42 s 过曝。这是主动掩盖，不是被动对齐：允许 1 px 的错位，因为没人能在全白的一瞬间看见它。

为什么灯距要整除周长：295 m / 9 m = 32.8，不整除。运行时会把 spacing 改成 length / round(length/spacing) = 295/33 ≈ 8.94 m。差 6 cm，肉眼不可见，但接缝处不会出现半盏灯。

09关键算法Core Algorithms

9.1 弧长参数化（速度均匀的唯一步骤）

直接对参数 u 线性推进，速度会忽快忽慢，闭环处最明显。必须先建一张弧长表，再按米取点。

// 一次构建，之后每帧 O(1)
const N = 4096, pts = [], cum = [0];
for (let i = 0; i <= N; i++) pts.push(pathAt(i / N * TAU));
for (let i = 1; i <= N; i++) cum[i] = cum[i - 1] + dist(pts[i - 1], pts[i]);
const total = cum[N];

// 均匀重采样成 0.5 m 一格，得到 pos[] 与 tan[]
const step = 0.5, M = round(total / step);
for (let k = 0; k < M; k++) {                              // 二分查找 u，线性插值
  const u = uAtLength(k * step);
  pos[k] = pathAt(u);
  tan[k] = normalize(dlengthAt(u));
}

9.2 重力对齐标架（镜头不歪的关键）

function frameAt(T) {                    // T = 单位切线
  let U = sub([0, 1, 0], scale(T, T[1]));     // 世界上向剔除切向分量
  if (len(U) < 1e-3) U = [0, 0, 1];        // 竖直段退化保护
  U = normalize(U);
  const R = normalize(cross(U, T));         // 右
  return [R, cross(T, R)];                 // 右, 上
}

9.3 马蹄形截面（拱 + 平路面）

function sectionAt(deg) {
  if (deg >= 225 && deg <= 315) {           // 底部 90° 压成弦，就是路面
    const t = (deg - 225) / 90;
    return [W_FLOOR * (-1 + 2 * t), FLOORY];
  }
  const a = deg * Math.PI / 180;
  return [RAD * Math.cos(a), RAD * Math.sin(a)];
}

9.4 曲率 → 侧倾（姿态可信的全部秘密）

滑手不需要骨骼动画，只需要三件事：膝盖随节奏微屈、身体压向弯心、板面随坡度俯仰。曲率从前方 6 m 预读，避免「先歪后弯」。

const kappa = curvatureAt(s + 6);              // 1/m，带符号
const lean  = clamp(kappa * speed² * gain, -MAX, MAX); // 向心加速度 → 侧倾角
const bob   = Math.sin(t * bobFreq) * bobAmp;      // 呼吸/蹬地节奏
const pitch = -slopeAt(s) * pitchGain;            // 上坡抬板头
rider.rotation.set(pitch, yaw(s), lean);
rider.knees(crouch + bob);                       // 只有一个自由度

为什么这两个公式够用：在 100 px 高的背影上，人眼能分辨的信息只有「重心高低、朝向、板的角度」。这三个量恰好都有物理来源（曲率、坡度、节奏），所以看起来「像真的在滑」，而不像在飘。

9.5 确定性随机（每圈必须一模一样）

墙上的装饰、裂缝、涂鸦位置如果用 Math.random()，每圈都会变——那就不是闭环了。所有装饰的随机种子 = 环索引。

function rng(seed) { return () => (seed = (seed * 1664525 + 1013904223) >>> 0) / 4294967296; }
const r = rng(ringIndex * 7919);               // 第 7 环永远长在同一个位置

10内容管线Content Pipeline

你的强项是「出图 + 分镜」，这个项目要把它接上 3D。接法不是从零建模，而是用图定调，用代码造形。

  1. 出 12 张氛围图，只选 1 张当锚定帧

    用你现有的出图流程（超分、统一色调）跑 12 张隧道氛围稿，只挑一张作为「色彩与光的宪法」。其余 11 张的价值是排除法。

  2. 从那张图里只提取 5 个值

    主色、辅色、暗部色、雾色、高光色。写进 palette 字段。图的其余信息一律不追——纹理靠程序生成，形状靠代码。

  3. 隧道由代码生成，只做贴图

    管壁、拱肋、路面全部程序化。唯一需要的外部资产是一张 512×512 可平铺噪声，用来打破 CG 的均匀感。这是整个项目里最省成本的决定。

  4. 滑手用「低模 + 剪影」，不从零绑定

    一个 8k 面的基础人形，摆出一个滑行基准姿势，压成纯黑材质，加 1 px 边缘光。不做绑定、不做动画——姿态由 9.4 的三个公式驱动。

  5. 预设化，然后批量出缩略图

    每套预设自动抓 t=0.2 的一帧生成 thumbnail.jpg，保证商店页风格统一。这一步必须自动化，否则做十套预设会崩。

分辨率与宽高比

  • 垂直 FOV 锁定：不管 16:9 还是 21:9，垂直视角固定 56°，超宽屏自然获得更多左右（隧道壁），不会把人物拉变形。
  • 21:9 / 32:9：人物锚点从 0.56W 右移到 0.62W，避免在超宽屏上正中悬空。
  • 竖屏 / 双屏：竖屏时把机位抬高、FOV 收窄；双屏时两台实例相位错开 length/2，避免两个屏完全同步（同步会显得假）。
  • 4K：dpr 上限 1.5，几何不变，只提采样；4K 下强制 30 fps 上限。

13里程碑与判死门Milestones & Gates

五个阶段，总共约五周（业余时间）。每个阶段末尾有一个判死门：不通过就回到上一阶段，而不是「先做完再看」。这是防止两周做出一个不好看的东西的唯一办法。

M0 · 2 天 · 已完成 构图样机 2D Canvas 线条光样机，三套预设、三种机位、接缝过曝。 门：把这一帧贴在桌面上，看 60 秒，还想看吗？
M1 · 1 周 闭环管道 Three.js 马蹄形管壁 + 弧长参数化 + 相机跟随 + 单文件打包。 门：连续盯 40 分钟看不出重复；1440p ≥ 30 fps。
M2 · 1 周 剪影滑手 低模 + 程序化姿态 + 三种机位 + 边缘光。 门：找 5 个不看说明的人，≥ 3 个能说出「他在滑板」。
M3 · 1 周 预设与壳 三套隧道、设置面板、Lively + WE 双打包、缩略图自动化。 门：换预设 < 1 s；冷启动 < 1.5 s；两个平台都能装。
M4 · 1 周 长时演化与发布 18 min 大周期、微事件、8 h 漂移、省电模式。 门：挂机 8 小时不崩、显存不涨、90 秒内出现一次可见变化。

判死门怎么用：不过门就不进入下一阶段，先修当前阶段。M0 不过（静帧不好看）→ 不做 3D；M1 不过（跑不到 30 fps）→ 退回「预渲染环 + 2D 视差」，那是你已经有能力交付的形态；M2 不过（人看不出在滑板）→ 把角色改成纯剪影+速度拖影，放弃可识别性。

15验收清单Acceptance

每一条都必须能当场演示，不允许「大概可以」。

  • 无缝：连续观察 40 分钟，指出循环接缝的具体秒数——做不到即通过。
  • 姿态：截取 5 张不同弯道的静帧，滑手重心方向与弯心方向一致。
  • 尺度：人物身高与隧道净高比例在 1:3.2 ± 0.2 之间（一眼不像玩具）。
  • 可读性：叠加 20 个 32 px 桌面图标后，图标识别时间 < 1.2 s。
  • 切换：三套预设切换均 < 1 s，且切换瞬间不闪黑、不重建曲线。
  • 性能：1440p 下稳态 ≥ 30 fps，挂机 30 min 后帧率不低于首帧的 90%。
  • 长时：挂机 8 h 不崩、不内存泄漏（显存增长 < 30 MB）。
  • 宿主机：Lively 与 Wallpaper Engine 均可安装、可暂停、可恢复。
  • 单文件：dist/index.html 双击即可运行，不依赖本地服务器。
  • 降级：手动把帧率压到 20 fps，能观测到 Q1→Q3 的自动降级。

16路线图Roadmap

v1 是「一条隧道做得足够好」，v2 才是「很多条隧道」。顺序不能反——系列化的前提是第一个能挂住。

  • v1.0 · 三套预设（第 5 周）

    钠灯山体 / 冷白管廊 / 霓虹下穿。双平台可装，缩略图自动化。这是「可以给别人看」的第一个版本。

  • v1.2 · 时间与声音（+2 周）

    18 分钟大周期、微事件剧本、可选环境音（默认静音）。这一步决定它能不能被挂一个月。

  • v1.5 · 自定义（+3 周）

    让用户改三件事：灯色、灯距、坡度。不做曲线编辑器——那会毁掉美术下限。改完可导出成 JSON 分享。

  • v2.0 · 第二卷：海底隧道（+4 周）

    换标架（RMF）、换介质（水）、换生物（鱼群剪影）。技术复用 80%，是验证「引擎可系列化」的关键一步。

  • v2.x · 系列化与分发

    废弃矿道 / 极地管线 / 太空环。做成「卷」的合集（Vol.1–3），Wallpaper Engine 上架 + 本地直发双轨。

    • 收入模型（如果要做）：不卖单张，卖「卷」。一卷 = 3 套隧道 + 1 套角色轮廓，定价按壁纸引擎的常规区间。真正的长期价值是 v1.5 的自定义导出——用户生成的预设会变成免费的内容更新。
